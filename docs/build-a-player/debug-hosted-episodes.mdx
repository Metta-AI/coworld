---
title: "Debug hosted episodes"
description: "Find a policy episode, inspect its failure evidence, and open an available replay."
---

Start every hosted investigation from its episode request. It ties the participants, status, scores, errors, logs, and
replay to one `ereq_...` ID.

## Find an episode

Filter by policy name, version, or policy-version UUID:

```bash
uv run coworld episodes \
  --policy my-player:v3 \
  --json
```

Use `--round round_...` instead of `--policy` when you want every episode in one round. These are alternative root
selectors, so one command cannot combine them. Add `--with-replay` only when you want rows with replay data.

Inspect one row directly:

```bash
uv run coworld episodes ereq_... --json
```

Check `status`, participant scores, `error`, and `error_type` first. Completed episodes may include a `replay_url`,
while running episodes may include a `live_url`.

## Collect many evaluation batches

Read results for up to 50 batches together. `--json` returns one page with `next_cursor`; pass it to `--cursor`.
`--jsonl` streams all pages, one JSON page per line. Pages contain at most 200 episodes.

```bash
uv run coworld xp-request episodes xreq_first xreq_second --view results --jsonl
```

Use `--view progress` for status-only reads. Repeat `--status` to filter execution states.
You can also select explicit `ereq_...` IDs; do not mix episode and batch IDs.

Follow changes without repeatedly fetching every episode:

```bash
uv run coworld xp-request watch xreq_first xreq_second \
  --view results --checkpoint ./watch.json --timeout 3600 --jsonl
```

Rerun the same command to resume. Output contains snapshot pages followed by change pages; duplicates are possible.
Apply entries by episode ID and accept revisions equal to or greater than the saved revision. Apply `removed` entries as deletions.
Save `next_cursor` after processing the page. The CLI saves its checkpoint after flushing output.

The default `--until execution` stops when execution finishes. To wait for final evidence, add
`--until evidence --include results --include player_logs`. File publication can finish after execution does.
An expired cursor or changed access stops the watch. Check permissions and use `--reset` to create a new snapshot.

Download only the evidence you need:

```bash
uv run coworld xp-request download xreq_first xreq_second \
  --include results --include player_logs --directory ./evidence --concurrency 4
```

Repeat `--include` for `results`, `replay`, `events`, `error_info`, `game_logs`, `player_logs`, or `player_artifact`.
Repeat `--agent N` to narrow player evidence. Permissions still apply to every selected player.

Downloads go directly to storage with four concurrent transfers by default, configurable up to sixteen.
`manifest.jsonl` records relative paths, availability, versions, byte counts, and local SHA-256 hashes without signed URLs.
Versioned directories keep different objects separate. Rerunning verifies completed files and retries incomplete transfers.
Interrupted files restart from the beginning. Stored compression is preserved; inspect each receipt's `encoding` before decoding.

Exit status `0` means completion, including optional files marked `not_produced`. Status `2` means failed execution,
unavailable selectors, or pending/unavailable downloads. Watch status `3` means timeout. Invalid commands and request failures exit `1` or `2`.
Watch respects server polling guidance and `Retry-After`, backing off during idle periods.

## Read logs and artifacts

Print the game log:

```bash
uv run coworld episode-logs ereq_... --game
```

Download it instead:

```bash
uv run coworld episode-logs ereq_... \
  --game \
  --download-dir ./evidence
```

List player logs available to your memberships, then inspect one slot:

```bash
uv run coworld episode-logs ereq_... --list --mine
uv run coworld episode-logs ereq_... --agent 0 --mine
```

If that player uploaded an artifact, download it separately:

```bash
uv run coworld episode-logs ereq_... \
  --agent 0 \
  --artifact \
  --mine \
  --download-dir ./evidence
```

Player logs and artifacts are ownership-scoped. You cannot read another owner's private policy evidence through an
ordinary credential.

For `platform-hosted` players, the runner captures each container's logs. For `game-hosted` players, the game writes
seat logs. A game-declared player failure assigns a terminal seat fault; `player_status.json` alone is diagnostic.
See the [failure contract](https://github.com/Metta-AI/coworld/blob/main/src/coworld/docs/artifacts/ERROR_INFO.md).

## Open a replay when available

When the episode row includes a `replay_url`, open it through the Coworld's viewer.

Open the episode through its declared viewer:

```bash
uv run coworld replay-open ereq_...
```

Static bundles open through Observatory without a game runtime. Coworlds without `game.replay_viewer` use the game
image on local Docker.

For either replay-viewer type, ask Observatory for a hosted viewer session:

```bash
uv run coworld replay-open ereq_... --hosted
```

Treat the stored replay as opaque game-owned bytes. Use the viewer shipped by that Coworld.

Experience Requests and scheduled league rounds both produce `ereq_...` episode IDs. Create controlled hosted runs with
[Upload and evaluate](/docs/coworld/build-a-player/upload-and-evaluate), then continue with [Improve a policy](/docs/coworld/build-a-player/improve-a-policy).
